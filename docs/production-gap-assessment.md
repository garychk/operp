## 一、结论摘要

**账务与计划内核达到了国产中型 ERP 的水准；但「车间执行」这一层是空的 —— 生产订单没有工序，报工无处挂靠，进度只能靠完工入库反推。**

一句话概括：**能算（MPS/MRP/成本卷算）、能记账（领料/完工/委外全闭环）、能看料（齐套/预占/ATP），但「怎么把一张工单在车间里跑完」这条路是断的。**

按客户类型给结论：

| 客户类型 | 能否现在就卖 | 说明 |
|---|---|---|
| 贸易 / 纯购销 | ✅ 能 | 生产模块非必需；库存+财务已够（见库存评估 93% 核心覆盖） |
| **按单简单组装**（一料到底、单工序或纯组装） | ⚠️ 勉强能 | BOM 展开→领料→完工入库→成本卷算链路完整；缺成品检验与工单进度看板 |
| **离散制造（多工序/车间流转）** | ❌ 不能 | **工单无工序、无派工、无工序进度**，客户第二天就会问「我的活儿走到哪一道了」 |
| 流程制造（配方/联副产品/批次） | ❌ 不能 | 无联副产品、无批次主数据与效期、无流程行业配方管理 |
| 项目制造 / ETO | ❌ 不能 | 无项目号贯穿、无设计变更（ECN）、无按项目归集成本 |

| 维度 | 现在 | 说明 |
|---|---|---|
| 基础主数据（BOM/工艺/工作中心） | ★★★★☆ | BOM 多版本+损耗+按工序+虚拟件；工艺路线有明细序列；**缺替代料、缺设备/模具台账** |
| 计划（MPS/MRP） | ★★★★☆ | LLC 分层/净需求/批量规则/提前期倒排/幻影穿透/转单追踪，已达可用水准；**缺工作日历、max_qty、DRP、有限产能** |
| 生产订单（工单） | ★★☆☆☆ | 头+材料行+BOM展开+齐套+状态字段齐备；**但无工序明细、无派工、无拆合单、无变更、无进度回写** |
| 车间执行 | ★☆☆☆☆ | 仅「报工登记（工时/产出）」；**不回写进度、无倒冲、无计件工资、无车间看板、无扫码** |
| 领退料 | ★★★☆☆ | 领料/退料/齐套生成领料已闭环；**无倒冲、补料弱、未按工序领料** |
| 完工入库 | ★★★★☆ | 过账/成本/库位/批次列/反过账齐；**未接成品检验** |
| 委外 | ★★★★★ | 订单/发料/入库/核销/结算/反过账全闭环，凭证口径正确 |
| 成本核算 | ★★★☆☆ | 材料/人工/制费卷算 + 在制跨期滚动；**无标准成本、无差异分析、无约当产量、无成本还原** |
| 质量 | ★★★☆☆ | 来料检/工序检/退货检 + 检验项目 + 与库存状态联动；**无成品入库检、无抽检方案、无返修流程、无追溯** |
| 生产报表/看板 | ★☆☆☆☆ | **几乎为零**：无生产进度表、无工单成本表、无在制报表、无产能负荷表、无良率报表 |
| 平台/工程（多租户/权限/审计/幂等） | ★★★★★ | 远超多数国产 ERP，是差异化的加分项 |

## 三、已经具备的能力（不必重做）

| 能力 | 实现位置 | 备注 |
|---|---|---|
| 多层 BOM + 多版本 + 生效/失效期 + 默认版本 | `erp_boms` / `erp_bom_details`（deploy_01） | `version` / `effective_date` / `expiry_date` / `is_default` / `is_active` |
| BOM 用量含损耗率 | `erp_bom_details.loss_rate`（小数，0.05=5%） | `explode_production_order_bom` 内 `× (1+loss_rate)`，**不 ÷100** |
| BOM 行归属工序 | `erp_bom_details.operation_id` | 为「按工序领料」预留，目前领料未消费该字段 |
| 虚拟件（幻影件）穿透 | `erp_boms.is_phantom` | MRP 引擎 blow-through |
| 工艺路线（头 + 工序序列） | `erp_routing_operations` + `erp_routing_operation_details` | 明细含 `sequence_no` / `standard_hours` / `setup_hours` / `next_operation_id` / `is_inspection_required` |
| 工序主数据 / 工作中心 / 产能费率 | `erp_operations` / `erp_work_centers` | 含 `capacity_per_day` / `labor_rate` / `overhead_rate` |
| 物料制造/采购属性 | `erp_products`（deploy_60） | `is_manufactured` / `is_purchased` / `is_phantom` / `is_mrp_relevant` / `lead_time_purchase` / `lead_time_production` / `order_point` / 安全库存 |
| MRP 运算引擎 | `ai-server/src/services/mrpEngine.ts` | 低层码分层 + 逐日净需求 + 批量规则（`lot_for_lot`/`fixed_qty`/`multiples`）+ 提前期倒排 + 幻影穿透；纯函数可复现 |
| MRP 计划转单 | `mrpConvertService.ts` | 计划订单 → 采购订单草稿 / 生产订单，带转单追踪防重复下单 |
| MPS 主生产计划 + 确认锁定 + 下推 MO | `erp_mps_plans*` + `mpsService.ts` | 确认整单锁定；一行一产品下推一张 MO；台账 `pushed_quantity` 回写 |
| RCCP 粗能力校验 | `POST /api/mps/rccp` | 月产能 = `capacity_per_day × 自然日数`（纯计算不落表） |
| 生产订单 BOM 展开 / 齐套检查 | `explode_production_order_bom` / `production_kit_check` | 齐套按物料聚合、四态（done/ready/transfer/short），**刻意不做审批流** |
| 生产领料 / 完工入库过账 | `post_production_document`（**最新定义 deploy_93**） | 移动加权成本、带符号流水、`pg_advisory_xact_lock`、幂等键、可反过账 |
| 生产退料 | `erp_material_returns*`（deploy_91 + deploy_93） | 回冲领料成本 |
| 领料需求预占（ATP） | `reserve_production_order_stock`（deploy_100/101） | 按 FIFO 摊分，缺口不污染可用量 |
| 生产报工登记 | `erp_production_reports` + `ProductionReports.tsx` | 工序/工作中心/操作工/完工数/报废数/工时/机时；`confirmed` 才计成本 |
| 成本卷算 | `costRollupService.ts` | 材料=已过账领料、人工=已确认报工工时×费率、制费=机时×费率；完工>0 全额结转，期末在制跨期滚动 |
| 委外全流程 | `erp_subcontract_*`（deploy_102/103） | 订单/发料/入库/核销/结算/反过账；凭证 1405/1408/2202 三行 |
| 质量检验单 + 检验项目 | `erp_quality_inspections` / `_items`（deploy_10） | 来料检/工序检/退货检；项目含标准/方法/实测值/判定/缺陷描述 |
| 质检 ↔ 库存状态联动 | `apply_quality_inspection_stock_move`（deploy_100） | 检验完成自动搬桶（available/hold/rejected）；支持「入库即待检」 |
| 单据编号 / 幂等 / 反过账 / 审计日志 / 多租户 | 平台层 | 工程完整度是相对多数国产 ERP 的**加分项** |

## 四、差距清单（按域）

状态：✅ 已有　⚠️ 部分　❌ 缺失

### A. 基础主数据

| # | 状态 | 缺口 | 现状证据 | 标准 ERP 应有 | 售卖影响 |
|---|---|---|---|---|---|
| A1 | ❌ | **替代料 / 替代 BOM** | 全库搜「替代料」仅 1 处注释（deploy_102）；`erp_bom_details` 无替代组/替代优先级/替代比例 | 替代料组、替代优先级、替代 BOM、替代后重新展开 | 电子/装配类客户高频；缺此则改料必须改 BOM |
| **A2** | ❌ | **设备 / 模具 / 工装台账** | 全库搜「设备/equipment/mold/模具」→ 0 张表（仅法务文案命中） | 设备台账、设备产能、模具寿命/保养、设备状态 | 有自有设备与模具的客户会问；影响产能与成本归集 |
| A3 | ⚠️ | 批量规则不全 | `mrpEngine.ts` 仅 `lot_for_lot/fixed_qty/multiples`，**`max_qty` 未实现**（引擎显式 warning） | 逐批/固定量/倍数/最大批量/最小批量/周期批量 | 计划员日常参数，缺则计划量不贴合采购/生产约束 |
| A4 | ❌ | 物料管理属性开关 | `erp_products` 无批次/序列号/保质期/计价方法开关（库存评估 E1） | 按物料开关管理粒度 | 与批次追溯强绑定 |
| A5 | ⚠️ | BOM 行无独立生效期/替换关系 | `erp_bom_details` 无行级生效期、无替换关系 | 行级有效期、替换链 | 工程变更场景需要 |
| A6 | ⚠️ | 工艺路线无资源/工装/技能要求 | `erp_routing_operation_details` 无「所需设备/工装/技能等级」 | 工序资源需求 | 排产与产能测算需要 |

### C. 生产订单（工单）—— **最大结构性短板**

| # | 状态 | 缺口 | 现状证据 | 标准 ERP 应有 | 影响 |
|---|---|---|---|---|---|
| **C1** | ❌ | **工单无工序明细（工序任务）** | `erp_production_order_details` 的字段是 `material_id/planned_quantity/issued_quantity/warehouse_id` → **是「材料行」不是「工序行」**；全库搜 `order_operation / dispatch / flow_card / job_card` → **0 张表** | 工单下达时按工艺路线生成工序行（工序/工作中心/计划工时/状态/派工对象） | 无法回答「工单跑到哪道工序」，无法按工序报工/派工 |
| **C2** | ❌ | **报工不回写订单/工序进度** | 设计决策 #8：报工不产生库存流水、**不回写订单进度**，进度以完工入库为准 | 报工即更新工序完工数与工单进度 | 车间看不到进度，销售催货无处查 |
| C3 | ❌ | 无派工 / 流转卡 / 工序交接 | 无任何派工表与流转卡 | 派工单、工序流转、交接确认 | 车间管理刚需 |
| C4 | ⚠️ | 工单状态机无动作入口 | 状态字段齐（`draft/planned/released/in_progress/completed/closed/cancelled`），但页面动作只有 展开/齐套/生成领料/预占/编辑；**无「下达/开工/完工/关闭」显式按钮**，且 `status` 无 DB CHECK 约束 | 状态迁移按钮 + 状态守卫 + 审计 | 状态可信度与操作体验 |
| C5 | ❌ | 拆单 / 合单 / 分批 | 无 | 按批量拆单、多单合并、分批投产 | 大批量客户 |
| C6 | ❌ | 工单变更 / ECN | 无 | 设计变更、数量变更留痕 | ETO/工程变更客户 |
| C7 | ❌ | 期初在制工单 | 库存有期初开账，**生产侧无期初在制工单** | 上线切换时的在制余额承接 | 存量客户切换必踩 |
| C8 | ❌ | 工单审批流 | `doc_flow_rules` 内无生产类；`mrp/*` 刻意不做审批 | 下达前审批（主管/计划） | 中大型客户合规要求 |

### I. 质量

## 八、售卖话术的风险提示

现有宣传文案（`docs/production-planning-marketing.md`）主打「MPS+MRP+成本全闭环」，**账面对得上，但有两个隐含承诺要小心**：

1. **「生产执行——单据闭环，账实一致」** —— 现在指的是**物料账**闭环（领料/入库/成本）。若客户理解为「车间执行管理」，会立刻撞上「工单无工序」的墙。建议话术明确为「**物料与成本闭环**」，工序执行留待 P0-1。
2. **「成本自动卷算」** —— 要补一句「**支持在制跨期结转**」作为边界说明，避免客户按「精细化在制/约当产量」预期验收（H3）。
3. **AI 只解读不计算的定位是加分项**，建议保留并强化 —— 这是相对国产 ERP 的**差异化亮点**。

**销售侧建议的分层话术**：
- 对贸易/简单组装客户：主打库存 + 财务 + 委外（成熟度 90%+），生产模块作为加购。
- 对离散制造客户：**先补 P0-1~P0-5，再进该类客户**；否则以「试点」而非「正式上线」承诺。

## 九、证据与验证方式

### 关键证据语句（可复现）

```bash
# 1. 生产订单明细是「材料行」不是「工序行」
#    → material_id / planned_quantity / issued_quantity / warehouse_id，无 operation_id
grep -n "erp_production_order_details" supabase/tables/deploy_01_schema_and_seed.sql

# 2. 全库无工单工序/派工/流转卡表
grep -rniE "CREATE TABLE.*erp_[a-z_]*(order_operation|dispatch|flow_card|job_card)" supabase/tables/*.sql
#   → 空

# 3. 成品入库检验未接通（source_type 无 production_receipt）
grep -n "source_type.*CHECK" supabase/tables/deploy_10_quality_inspection.sql
#   → CHECK(source_type IN('purchase_receipt','sales_return','production_operation'))

# 4. 无标准成本
grep -riE "标准成本|standard_cost" supabase/tables src ai-server/src
#   → 空

# 5. 报工不回写进度、不产流水（实现文档决策 #8）
grep -n "不回写\|不产生库存流水" docs/production-planning-implementation.md

# 6. 无排产/APS
grep -riE "排产|APS|scheduling" supabase/tables src ai-server/src
#   → 仅 Dashboard 的 snapshot 变量名误命中
```

### 建议的验收方式（补功能时）

- P0-1：下达工单 → 工序行生成 → 逐序报工 → 进度按比例推进 → 末序完工自动触发入库建议；断言工序工时合计 = 工艺路线标准工时。
- P0-2：完工入库「入库即待检」→ 生成检验单 → 判定 qualified/hold/rejected → 库存桶正确流转。
- P0-3：标准成本建档 → 实际卷算 → 四类差异（材料价差/量差、人工差、制费差）逐项可核对，且借贷平衡。
- P0-4：同一物料配 `max_qty` → 净需求批量结果符合上限；跨周末的提前期倒排落在工作日。
- P0-5：四张报表数字与 `deploy_93` 过账流水逐笔勾稽。
